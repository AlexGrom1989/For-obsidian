#### 1. Гипотеза исследования

**Гипотеза:** Различные AutoML фреймворки способны автоматически создавать эффективные модели для предсказания уровня грамотности населения на основе социально-экономических показателей стран. При этом предполагается, что:

1. Автоматизированные подходы к машинному обучению (AutoML) смогут выявить сложные нелинейные зависимости между экономическими показателями и уровнем образования
2. Различные AutoML фреймворки продемонстрируют разную эффективность в решении данной задачи регрессии
3. Лучшие модели достигнут приемлемой точности (R² > 0.7) для практического применения
4. AutoML подходы окажутся более эффективными по времени разработки по сравнению с ручной настройкой моделей

#### 3. Предобработка данных

##### 3.1 Инженерия признаков

Для улучшения качества предсказаний были созданы дополнительные признаки:

```python
def feature_engineering(df):
    df = df.copy()
    
    # Индекс доступности здравоохранения
    df['healthcare_access_index'] = df['Physician Density'] * np.log1p(df['GDP per Capita (Current USD)'])
    
    # Взаимодействие ВВП и безработицы
    df['gdp_unemployment_interaction'] = df['GDP Growth (% Annual)'] / (df['Unemployment Rate (%)'] + 1)
    
    # Логарифмические преобразования для снижения влияния выбросов
    df['log_gdp'] = np.log1p(df['GDP (Current USD)'])
    df['log_gdp_per_capita'] = np.log1p(df['GDP per Capita (Current USD)'])
    
    # Кодирование категориальных признаков
    gdp_category_map = {'Very Low': 1, 'Mid': 2, 'Low': 3, 'High': 4, 'Very High': 5}
    df['gdp_category_encoded'] = df['GDP per Capita Category'].map(gdp_category_map)

    cont_map = {'Asia': 1, 'Europe': 2, 'Africa': 3, 'North America': 4, 'South America': 5, 'Oceania': 6}
    df['continent_encoded'] = df['Continent'].map(cont_map)

    df.drop(columns=['GDP per Capita Category', 'Continent'], inplace=True)
    
    return df
```

##### 3.3 Предобработка в AutoML моделях

Каждый AutoML фреймворк применял собственные методы предобработки:

**LightAutoML:**
- Автоматическое определение типов признаков
- Встроенная обработка категориальных переменных
- Автоматическое масштабирование

**Fedot:**
- Автоматический выбор методов предобработки в рамках пайплайна
- Применение полиномиальных признаков (poly_features)
- Масштабирование (scaling)

**TPOT:**
- Генетический алгоритм для оптимизации пайплайна предобработки
- Кросс-валидация с 5 фолдами

**mljar-supervised:**
- Режим "Perform" с полным циклом предобработки
- Автоматическое создание признаков (golden_features)
- Селекция признаков (features_selection)

##### 4.2 Fedot

**Конфигурация:**
```python
automl = Fedot(
    problem='regression',
    timeout=5,
    preset='auto',
    n_jobs=4,
    safe_mode=True,
    with_tuning=False

```

**Пайплайн:**
```
Input → knnreg → poly_features → xgboostreg → scaling → poly_features → catboostreg → Output
```

**Описание:** Сложный последовательный пайплайн глубиной 6 уровней:
1. **knnreg** - k-ближайших соседей (k=20, uniform weights)
2. **poly_features** - генерация полиномиальных признаков
3. **xgboostreg** - XGBoost регрессор
4. **scaling** - масштабирование признаков
5. **poly_features** - повторная генерация полиномиальных признаков
6. **catboostreg** - CatBoost регрессор

##### 5.2 Объяснение выбора метрик

**RMSE (Root Mean Square Error):**
- Основная метрика для регрессии
- Штрафует большие ошибки сильнее малых
- Измеряется в тех же единицах, что и целевая переменная (%)

**MAE (Mean Absolute Error):**
- Средняя абсолютная ошибка
- Более устойчива к выбросам
- Интерпретируется как средняя ошибка в процентных пунктах грамотности

**R² Score (Коэффициент детерминации):**
- Показывает долю объясненной дисперсии
- Значения от 0 до 1, где 1 - идеальное предсказание
- Позволяет оценить качество модели относительно простого среднего

##### 5.3 Анализ результатов

**Лучшая модель: mljar-supervised**
- Достигла наивысшего R² = 0.7251 (объясняет 72.5% дисперсии)
- Наименьшая RMSE = 9.44%, что соответствует средней ошибке ~9% грамотности
- Сбалансированные показатели точности и обобщающей способности
- Использует продвинутые техники создания признаков и ансамблирования

**Второе место: TPOT**
- Показал лучшую MAE = 5.51%
- R² = 0.7164 - близко к лидеру
- Эффективная оптимизация через генетический алгоритм
- Хорошая автоматизация выбора алгоритмов

**Третье место: LightAutoML**
- Значительно быстрее конкурентов (17 секунд против 5 минут)
- R² = 0.6931 - приемлемое качество
- Простой и надежный пайплайн
- Оптимален для быстрого прототипирования

**Четвертое место: Fedot**
- Неудовлетворительные результаты (R² = 0.11)
- Переобучение из-за сложности пайплайна
- Возможно, недостаточно времени для оптимизации
- Требует дополнительной настройки

#### 6. Выводы по работе

##### 6.1 Подтверждение гипотезы

**Гипотеза частично подтвердилась:**

**Подтвердилось:**
- AutoML фреймворки способны создавать эффективные модели (3 из 4 показали R² > 0.69)
- Различные фреймворки показали существенно разную эффективность
- Лучшие модели достигли приемлемой точности (R² = 0.72)
- AutoML значительно ускоряет процесс разработки

**Не подтвердилось:**
- Не все фреймворки смогли выявить сложные зависимости (Fedot показал плохие результаты)
- Целевое значение R² > 0.7 достигли только 2 из 4 моделей

##### 6.2 Целесообразность использования AutoML

**Преимущества AutoML:**

1. **Скорость разработки:** LightAutoML обучилась за 17 секунд, другие - за 5 минут
2. **Автоматизация:** Нет необходимости в ручном подборе алгоритмов и гиперпараметров
3. **Ансамблирование:** Автоматическое создание сложных ансамблей
4. **Предобработка:** Встроенные методы очистки и трансформации данных
5. **Воспроизводимость:** Фиксированные random_state обеспечивают стабильность результатов

**Недостатки AutoML:**

1. **Черный ящик:** Ограниченная интерпретируемость некоторых моделей (особенно Fedot)
2. **Ресурсозатратность:** Длительное время обучения для сложных фреймворков
3. **Переобучение:** Риск создания излишне сложных моделей
4. **Настройка:** Некоторые фреймворки требуют дополнительной экспертизы
##### 6.3 Заключение

AutoML демонстрирует высокую эффективность для задач предсказания социально-экономических показателей. Исследование подтвердило, что автоматизированные подходы способны создавать конкурентоспособные модели с минимальным участием эксперта. 

Наилучшие результаты показал **mljar-supervised** (R² = 0.725), что делает его рекомендуемым выбором для подобных задач. **LightAutoML** оптимален для ситуаций с ограниченным временем, а **TPOT** представляет интерес для исследования оптимальных архитектур моделей.

Использование AutoML целесообразно как для быстрого прототипирования, так и для создания production-ready решений в области анализа социально-экономических данных.
