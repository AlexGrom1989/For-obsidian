### ФУНКЦИИ SQL

#### Числовые
| Функция | Описание | Пример |
|--------|----------|--------|
| TRUNCATE(num, part) | Обрезает число до `part` знаков после запятой | `TRUNCATE(10.2355, 2)` → 10.23 |

#### Текстовые

| Функция                              | Описание                                                 | Пример                                    |
| ------------------------------------ | -------------------------------------------------------- | ----------------------------------------- |
| `LIKE`, `NOT LIKE`                   | Поиск по шаблону (`%` — любая строка, `_` — один символ) | `'abc' LIKE 'a%'` → true                  |
| `char_length(string)`                | Число символов в строке                                  | `char_length('abc')` → 3                  |
| `lower(string)`                      | В нижний регистр                                         | `lower('ABC')` → 'abc'                    |
| `substring(string [FROM a] [FOR b])` | Извлекает подстроку                                      | `substring('abcde' FROM 2 FOR 3)` → 'bcd' |
| `left(str, n)`                       | Первые `n` символов                                      | `left('abcde', 2)` → 'ab'                 |
| `split_part(str,' ',num)`            | split по строке                                          | `split('a b', ' ', 1)`  → 'a'             |

#### Дата и время
| Функция | Описание | Пример (результат) |
|---------|----------|-------------------|
| `YEAR(date)` | Год даты | `YEAR('2024-11-12')` → 2024 |
| `MONTH(date)` | Месяц (1-12) | `MONTH('2024-11-12')` → 11 |
| `DAY(date)` | День месяца (1-31) | `DAY('2024-11-12')` → 12 |
| `HOUR(time)` | Час (0-23) | `HOUR('12:34:56')` → 12 |
| `MINUTE(time)` | Минуты (0-59) | `MINUTE('12:34:56')` → 34 |
| `DATE_PART(part, date)` | Извлечь часть даты | `DATE_PART('month', '2024-11-12')` → 11 |
| `EXTRACT(field FROM source)` | Извлечь часть (возвращает double) | `EXTRACT(MONTH FROM '2024-11-12')` → 11 |
| `DATE_TRUNC(unit, date)` | Округлить дату до начала периода | `DATE_TRUNC('month', '2024-03-14')` → '2024-03-01' |
| `CURRENT_DATE` | Текущая дата | |
| `NOW()` | Текущие дата и время | |

| Операция | Пример | Результат |
|----------|--------|-----------|
| `date + integer` | `date '2001-09-28' + 7` | `date '2001-10-05'` |
| `date + interval` | `date '2001-09-28' + interval '1 hour'` | `timestamp '2001-09-28 01:00:00'` |
| `date - date` | `date '2001-10-01' - date '2001-09-28'` | `integer 3` |
| `date - integer` | `date '2001-10-01' - 7` | `date '2001-09-24'` |
| `DATEDIFF(part, start, end)` | `DATEDIFF('month', '2011-08-25', '2017-08-25')` | `72` |

#### Работа с NULL
| Функция/Оператор | Описание |
|------------------|----------|
| `IS NULL` / `IS NOT NULL` | Проверка на NULL |
| `COALESCE(val1, val2, ...)` | Возвращает первое не-NULL значение |
| `NULLIF(val1, val2)` | Возвращает NULL, если значения равны, иначе `val1` |
| `IFNULL(val, replace)` | Возвращает `val`, если не NULL, иначе `replace` |
### АГРЕГИРУЮЩИЕ ФУНКЦИИ

| Функция | Описание | Пример |
|---------|----------|--------|
| `COUNT(column)` | Количество строк в группе | `COUNT(order_id)` |
| `COUNT(DISTINCT column)` | Количество уникальных значений | `COUNT(DISTINCT customer_id)` |
| `SUM(column)` | Сумма значений | `SUM(order_amount)` |
| `AVG(column)` | Среднее значение | `AVG(order_amount)` |
| `MIN(column)` | Минимальное значение | `MIN(order_amount)` |
| `MAX(column)` | Максимальное значение | `MAX(order_amount)` |
| `PERCENTILE_CONT(N)` | Непрерывный перцентиль | `PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY amount)` |

**Особенности:**
*   `COUNT(*)` считает все строки, `COUNT(column)` игнорирует NULL.
*   `SUM`, `AVG`, `PERCENTILE_CONT` игнорируют NULL.
*   Если все значения NULL, `SUM`, `AVG`, `MIN`, `MAX` вернут NULL.

### УСЛОВНАЯ АГРЕГАЦИЯ

| Метод | Синтаксис | Пример |
|-------|-----------|--------|
| **FILTER** | `AGGR_FUNC(column) FILTER (WHERE condition)` | `SUM(amount) FILTER (WHERE status='paid')` |
| **CASE WHEN** | `AGGR_FUNC(CASE WHEN condition THEN value END)` | `SUM(CASE WHEN status='paid' THEN amount ELSE 0 END)` |

**Разница:**
*   `FILTER` — только фильтрация.
*   `CASE WHEN` — позволяет сложную логику с несколькими условиями (`WHEN...THEN...`).

### СКАЛЯРНЫЕ ПОДЗАПРОСЫ С АГРЕГАЦИЕЙ

| Тип | Описание | Синтаксис (пример) |
|-----|----------|---------------------|
| **Некоррелированный** | Вычисляется один раз для всего запроса. | `SELECT col, (SELECT AVG(amount) FROM table) AS avg_all FROM table;` |
| **Коррелированный** | Вычисляется для каждой строки внешнего запроса (зависит от её значения). | `SELECT col1, (SELECT AVG(amount) FROM table2 WHERE table2.id = table1.id) FROM table1;` |

### ПОРЯДОК ВЫПОЛНЕНИЯ ЗАПРОСА (EXECUTION ORDER)

1.  **FROM** (и JOIN)
2.  **WHERE** (фильтрация строк)
3.  **GROUP BY** (группировка)
4.  **HAVING** (фильтрация групп)
5.  **SELECT** (выбор столбцов и агрегация)
6.  **ORDER BY** (сортировка)
7.  **LIMIT** (ограничение вывода)
### ВИДЫ JOIN

| Тип JOIN                         | Описание                                                    | Результат (для таблиц A и B)                                   |
| -------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------- |
| **INNER JOIN** (или просто JOIN) | Пересечение. Только совпадающие строки.                     | Только строки, где есть соответствие в A и B.                  |
| **LEFT (OUTER) JOIN**            | Все строки из левой таблицы (A) + совпадения из правой (B). | Все строки A. Для отсутствующих соответствий в B — NULL.       |
| **RIGHT (OUTER) JOIN**           | Все строки из правой таблицы (B) + совпадения из левой (A). | Все строки B. Для отсутствующих соответствий в A — NULL.       |
| **FULL (OUTER) JOIN**            | Объединение. Все строки из обеих таблиц.                    | Все строки A и B. Отсутствующие соответствия заполняются NULL. |
| **CROSS JOIN**                   | Декартово произведение. Все комбинации строк.               | Каждая строка A соединяется с каждой строкой B.                |

### ОПЕРАЦИИ НАД МНОЖЕСТВАМИ (SET OPERATIONS)

| Операция          | Описание                                                                  | Дедупликация? |
| ----------------- | ------------------------------------------------------------------------- | ------------- |
| **UNION**         | Объединение двух наборов. Возвращает уникальные строки.                   | Да (неявная)  |
| **UNION ALL**     | Объединение с сохранением всех строк, включая дубли.                      | Нет           |
| **INTERSECT**     | Пересечение. Возвращает строки, присутствующие в **обеих** выборках.      | Да            |
| **INTERSECT ALL** | Пересечение с учётом кратности (минимальное число вхождений).             | Нет           |
| **EXCEPT**        | Разность. Возвращает строки из первой выборки, которых **нет** во второй. | Да            |
| **EXCEPT ALL**    | Разность с учётом кратности (вычитает поштучно).                          | Нет           |
### ОКОННЫЕ ФУНКЦИИ: ОСНОВЫ И СИНТАКСИС

**Синтаксис:**
```sql
ФУНКЦИЯ(выражение) OVER (
    [PARTITION BY столбец1, ...]
    [ORDER BY столбец1 [ASC|DESC], ...]
    [ROWS | RANGE BETWEEN ...]
)
```

| Компонент | Назначение |
|-----------|------------|
| `PARTITION BY` | Разделяет данные на группы (окна). Аналог `GROUP BY`, но без сворачивания строк. |
| `ORDER BY` | Определяет порядок строк внутри окна. Включает режим накопления (кумулятивный расчёт). |
| `ROWS/RANGE BETWEEN` | Задаёт границы окна (рамки) для расчёта. |

---

#### АГРЕГИРУЮЩИЕ ОКОННЫЕ ФУНКЦИИ

| Функция | Описание | Пример (окно) |
|---------|----------|---------------|
| `SUM(...) OVER (...)` | Сумма по окну. | `SUM(payment) OVER (PARTITION BY client)` |
| `AVG(...) OVER (...)` | Среднее по окну. | `AVG(payment) OVER (ORDER BY date)` |
| `COUNT(...) OVER (...)` | Количество по окну. | `COUNT(*) OVER (PARTITION BY city)` |
| `MIN(...) OVER (...)` | Минимум по окну. | `MIN(price) OVER (PARTITION BY category)` |
| `MAX(...) OVER (...)` | Максимум по окну. | `MAX(date) OVER (PARTITION BY user)` |

---

#### LAG И LEAD (СМЕЩЕНИЕ)

| Функция | Назначение | Синтаксис |
|---------|------------|-----------|
| **LAG** | Возвращает значение из **предыдущей** строки окна. | `LAG(column, steps) OVER (...)` |
| **LEAD** | Возвращает значение из **следующей** строки окна. | `LEAD(column, steps) OVER (...)` |

---

#### ROWS и RANGE BETWEEN: Управление границами окна

**Общий синтаксис:**
```sql
ФУНКЦИЯ(выражение) OVER (
    [PARTITION BY ...]
    [ORDER BY ...]
    ROWS|RANGE BETWEEN начало AND конец
)
```

---

#### ROWS (физические строки)

| Начало/Конец          | Описание                                 | Пример                                             |
| --------------------- | ---------------------------------------- | -------------------------------------------------- |
| `UNBOUNDED PRECEDING` | От начала раздела (первой строки окна)   | `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` |
| `n PRECEDING`         | n строк ДО текущей                       | `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`         |
| `CURRENT ROW`         | Текущая строка                           | `ROWS BETWEEN CURRENT ROW AND 1 FOLLOWING`         |
| `n FOLLOWING`         | n строк ПОСЛЕ текущей                    | `ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING`         |
| `UNBOUNDED FOLLOWING` | До конца раздела (последней строки окна) | `ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING` |

**Примеры ROWS:**
```sql
-- Кумулятивная сумма от начала раздела до текущей строки
SUM(value) OVER (ORDER BY date ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)

-- Скользящее среднее по 3 строкам (текущая, предыдущая, следующая)
AVG(value) OVER (ORDER BY date ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING)

-- Сумма предыдущей и текущей строки
SUM(value) OVER (ORDER BY date ROWS BETWEEN 1 PRECEDING AND CURRENT ROW)
```

---

#### RANGE (логические значения)

| Начало/Конец | Описание | Особенности |
|--------------|----------|-------------|
| `UNBOUNDED PRECEDING` | От начала раздела | Аналогично ROWS |
| `value PRECEDING` | Значение меньше текущего на amount | Для числовых типов и дат |
| `CURRENT ROW` | Значения, равные текущему | Включает все строки с одинаковым ORDER BY значением |
| `value FOLLOWING` | Значение больше текущего на amount | Для числовых типов и дат |
| `UNBOUNDED FOLLOWING` | До конца раздела | Аналогично ROWS |

**Примеры RANGE:**
```sql
-- Сумма всех строк с одинаковой датой (по ORDER BY date)
SUM(value) OVER (ORDER BY date RANGE BETWEEN CURRENT ROW AND CURRENT ROW)

-- Сумма за последние 7 дней от текущей даты
SUM(value) OVER (ORDER BY date RANGE BETWEEN INTERVAL '7 days' PRECEDING AND CURRENT ROW)

-- Сумма значений в диапазоне ±10 единиц от текущего значения
SUM(value) OVER (ORDER BY value RANGE BETWEEN 10 PRECEDING AND 10 FOLLOWING)
```

### РАНЖИРУЮЩИЕ ОКОННЫЕ ФУНКЦИИ

| Функция | Описание | Поведение при одинаковых значениях ORDER BY | Пример |
|---------|----------|---------------------------------------------|--------|
| **ROW_NUMBER()** | Порядковый номер строки | Всегда уникальные номера (1,2,3,4...) | `ROW_NUMBER() OVER (ORDER BY amount)` |
| **RANK()** | Ранг с пропусками | Одинаковый ранг → пропуск следующего номера (1,2,2,4...) | `RANK() OVER (ORDER BY age)` |
| **DENSE_RANK()** | Плотный ранг без пропусков | Одинаковый ранг → следующий номер без пропуска (1,2,2,3...) | `DENSE_RANK() OVER (ORDER BY score)` |

#### Операторы для границ:

| Оператор | Описание | Пример рамки |
|----------|----------|--------------|
| `UNBOUNDED PRECEDING` | От первой строки раздела | `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` |
| `n PRECEDING` | n строк ДО текущей | `ROWS BETWEEN 2 PRECEDING AND CURRENT ROW` |
| `CURRENT ROW` | Текущая строка | `ROWS BETWEEN CURRENT ROW AND 1 FOLLOWING` |
| `n FOLLOWING` | n строк ПОСЛЕ текущей | `ROWS BETWEEN CURRENT ROW AND 2 FOLLOWING` |
| `UNBOUNDED FOLLOWING` | До последней строки раздела | `ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING` |

### ОПТИМИЗАЦИЯ В GREENPLUM / POSTGRESQL**

---

##### **1. АНАЛИЗ ПЛАНА ЗАПРОСА**
- `EXPLAIN` — предварительный план (запрос не выполняется).
- `EXPLAIN ANALYZE` — фактический план + время выполнения, memory, loops.
- **Чтение плана:** снизу вверх, от самого вложенного узла.
- **Ключевые метрики:**
  - `cost` — относительная стоимость операции.
  - `rows` — ожидаемое/фактическое число строк.
  - `width` — средний размер строки в байтах.
  - `actual time` — время выполнения операции.

---

##### **2. ОСНОВНЫЕ ОПЕРАТОРЫ В ПЛАНЕ**
| Тип | Оператор | Когда используется |
|-----|----------|-------------------|
| **Чтение** | `Seq Scan` | Полное сканирование таблицы. |
| | `Index Scan` | Поиск по индексу с обращением к таблице. |
| | `Index Only Scan` | Только индекс, без таблицы. |
| **Соединение** | `Hash Join` | Чаще всего, оптимально для больших таблиц. |
| | `Merge Join` | Редко, требует предварительной сортировки. |
| | `Nested Loop` | Дорого, для маленьких таблиц или отсутствия индексов. |
| **Прочие** | `Sort` | Сортировка данных. |
| | `Hash Aggregate` | Группировка через хэш. |
| | `Materialize` | Материализация подзапроса. |
| | `Filter` | Применение условия WHERE. |
| | `Limit` | Ограничение числа строк. |

---

##### **3. ИНДЕКСЫ**
- **Создать:** `CREATE INDEX idx_name ON table (column);`
- **Удалить:** `DROP INDEX idx_name;`
- **Типы индексов:**
  - `B-Tree` — по умолчанию, для =, <, >, BETWEEN, ORDER BY.
  - `Hash` — только для точного совпадения (=).
  - `GIST` — для геоданных, JSONB, полнотекстового поиска.
  - `GIN` — для массивов, JSONB, текста.
  - `UNIQUE` — гарантия уникальности.
- **Составной индекс:** `CREATE INDEX idx ON table (col1, col2);`
- **Частичный индекс:** `CREATE INDEX idx ON table (col) WHERE condition;`

---

##### **4. СТАТИСТИКА**
- **Сбор:** `ANALYZE table_name;`
- **Сбор по полям:** `ANALYZE table_name (column1, column2);`
- **Проблема:** неактуальная статистика → неоптимальный план.
- **Решение:** регулярно обновлять статистику, особенно после больших изменений данных.

---

##### **5. GREENPLUM: ОСОБЕННОСТИ**
- **Архитектура:** Master (координатор) + Segments (обработка данных).
- **Ключ дистрибуции:** `DISTRIBUTED BY (column)` — определяет распределение строк по сегментам.
- **Перекос данных (Data Skew):**
  - **Выявление:** `SELECT gp_segment_id, COUNT(*) FROM table GROUP BY 1;`
  - **Решение:** изменить ключ дистрибуции, использовать `DISTRIBUTED RANDOMLY`.
- **Операторы движения данных:**
  - `Broadcast Motion` — копирование таблицы на все сегменты (для маленьких таблиц).
  - `Redistribute Motion` — перераспределение данных по новому ключу.
  - `Gather Motion` — сбор результатов на мастер.
  - **Цель:** минимизировать движение данных.

---

##### **6. ПАРТИЦИОНИРОВАНИЕ**
- **Цель:** уменьшение объёма сканирования.
- **Типы:** `RANGE` (по диапазону), `LIST` (по значениям).
- **Обязательно:** использовать условие на поле партиционирования в WHERE.
- **Default partition:** хранит данные, не попавшие в другие партиции.
- **Изменить партицию:** `ALTER TABLE ... ADD/DROP PARTITION ...`

---

##### **7. ТИПИЧНЫЕ ПРОБЛЕМЫ И РЕШЕНИЯ**
| Проблема | Симптом | Решение |
|----------|---------|---------|
| **Перекос данных** | Разное число строк на сегментах. | Изменить ключ дистрибуции, использовать `DISTRIBUTED RANDOMLY`. |
| **Большие движения данных** | `Broadcast Motion` для большой таблицы. | Локализовать JOIN по одинаковым ключам дистрибуции. |
| **Spill-файлы** | Нехватка памяти, запись на диск. | Увеличить `max_statement_mem`, оптимизировать распределение, переписать запрос. |
| **Замножение данных** | Резкий рост числа строк в плане. | Проверить условия JOIN, убрать декартово произведение. |
| **Неиспользование индексов** | `Seq Scan` вместо `Index Scan`. | Обновить статистику, проверить условие WHERE, создать индекс. |
| **Неиспользование партиций** | Сканируются все партиции. | Добавить условие на поле партиционирования в WHERE. |

---

##### **8. ЧЕК-ЛИСТ ОПТИМИЗАЦИИ**
1. **До запуска:** выполнить `EXPLAIN`.
2. **Фильтрация:** применять WHERE до JOIN.
3. **Выбор столбцов:** явно указывать список, не использовать `SELECT *`.
4. **Избегать:**
   - `OR` в условиях JOIN → заменить на `UNION ALL`.
   - `IN` с большими списками → заменить на JOIN.
   - Функций в условиях JOIN → предварительно вычислить в отдельном столбце.
   - `ORDER BY` на ранних стадиях → сортировать в конце.
   - `DISTINCT` → использовать `GROUP BY` или устранять дубли раньше.
   - `UNION` → использовать `UNION ALL` (если дубли не нужны).
5. **Подзапросы:** заменить на JOIN.
6. **Большие запросы:** использовать временные таблицы для переиспользования данных.
7. **Регулярно:** обновлять статистику (`ANALYZE`), мониторить перекос и spill-файлы.

---

##### **9. ПОЛЕЗНЫЕ ЗАПРОСЫ**

### НОРМАЛЬНЫЕ ФОРМЫ, DWH-СЛОИ И СТАНДАРТЫ ИМЕНОВАНИЯ**

---

#### **1. НОРМАЛЬНЫЕ ФОРМЫ (ДЛЯ DDS)**
| НФ | Правило | Цель в DDS | Пример нарушения |
|----|---------|------------|------------------|
| **1НФ** | Атомарные значения; нет повторяющихся групп; нет массивов в ячейках. | Устранить неструктурированность. | Поле `phone_numbers = '+7911, +7922'`. |
| **2НФ** | Находится в 1НФ; каждый неключевой атрибут зависит от **всего** первичного ключа (нет частичных зависимостей). | Устранить дублирование из-за части ключа. | В `OrderItems(order_id, product_id, product_name)` поле `product_name` зависит только от `product_id`. |
| **3НФ** | Находится в 2НФ; нет транзитивных зависимостей (неключевой атрибут зависит от другого неключевого). | Устранить косвенное дублирование. | `Customer(cust_id, zip_code, city)`: `city` зависит от `zip_code`. |
| **BCNF** | Каждый детерминант (левая часть ФЗ) — суперключ. | Усилить 3НФ, убрать зависимости от не-ключей. | `Class(student, teacher, subject)`, где `teacher → subject`. |
| **4НФ** | Нет многозначных зависимостей (когда несколько независимых наборов значений). | Устранить независимые многозначные связи. | `Employee(emp_id, skill, language)` — навыки и языки независимы. |
| **5НФ** | Нет зависимостей соединения (таблица не может быть восстановлена без потерь из проекций). | Устранить сложные составные зависимости. | Редко используется на практике. |

**Практическое правило для DDS:** **минимум 3НФ**, для справочников и ядра — BCNF.

---

#### **2. ОПРЕДЕЛЕНИЯ СЛОЕВ DWH**
| Слой | Полное название | Назначение | Характеристики |
|------|----------------|------------|----------------|
| **RAW** | Raw Data Layer | Сырые, неизменённые данные из источников. | Формат как в источнике; быстрое поглощение; часто партиционировано по дате загрузки. |
| **ODS** | Operational Data Store | Операционное хранилище. Актуальные, очищенные данные на near-real-time. | Очистка, стандартизация; поддержка операционных запросов; часто зеркалирует источник. |
| **DDS** | Detail Data Store (или Detailed Data Layer) | Детальный слой. Очищенные, нормализованные, историзированные данные для аналитики. | Высокое качество; нормализация; суррогатные ключи; версионирование; единый источник истины. |
| **DM** | Data Mart | Витрина данных. Денормализованные данные, подготовленные для конкретных бизнес-задач. | Оптимизирована под отчёты; содержит агрегаты; тематическая ориентация (например, Sales DM). |

**Поток данных:**  
`Источники → RAW → ODS → DDS → DM`

---
#### **3. Типы таблиц в DDS/DM**
| Тип | Описание | Примеры полей |
|-----|----------|---------------|
| **Измерение (Dimension)** | Справочники (клиенты, товары, даты) | `_rk`, `_id`, атрибуты, `valid_from_dttm` |
| **Факт (Fact)** | События/операции (продажи, заказы) | Ключи на измерения, меры (сумма, количество) |
| **Связь (Link)** | Связи «многие ко многим» (продукт-категория) | Составной ключ из `_rk` связанных сущностей |

---

#### **4. Data Vault (часть DDS)**
| Тип | Роль | Ключевые поля |
|-----|------|---------------|
| **Хаб (Hub)** | Уникальный бизнес-ключ сущности | `_rk`, бизнес-ключ, `source_system` |
| **Сателлит (Satellite)** | Атрибуты + история изменений | `_rk`, `valid_from_dttm`, `valid_to_dttm`, атрибуты |
| **Линк (Link)** | Связь «многие ко многим» между хабами | Ключи связанных хабов, возможно тип связи |

---

#### **7. Ключевые принципы**
- **Суррогатные ключи** (_rk) — генерируются в ХД, независимы от источников.
- **Технические поля** — `processed_dttm`, `valid_from_dttm`, `valid_to_dttm`, `deleted_flg`.
- **ELT** (а не ETL) — данные сначала загружаются «как есть», потом трансформируются в хранилище.
- **Схема «звезда»** — факт + несколько измерений (оптимизирована для запросов).

### МЕТОДЫ ЗАГРУЗКИ ВИТРИН ДАННЫХ INSERT UPSERT

| Метод                  | Суть                                                                 | Когда использовать                                                                                            | Плюсы                                                                         | Минусы                                                                                            |
|------------------------|----------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| **Полная перезапись**  | `TRUNCATE` + `INSERT` (удалить всё, загрузить заново)                | Небольшой объём данных, простая логика, история не нужна                                                      | Простота реализации, исключены ошибки дублирования                            | Долго на больших данных, высокая нагрузка на СУБД, теряется история                               |
| **Инкрементальный INSERT** | Добавление только новых строк (по `processed_dttm` или ID)         | Большие витрины, данные только добавляются (транзакции, снимки состояний)                                     | Быстро, низкая нагрузка, сохраняется история                                  | Не обновляет существующие данные; риск дубликатов при сбоях                                       |
| **UPSERT**             | `INSERT ... ON CONFLICT DO UPDATE` (вставить или обновить по ключу) | Нужно обновлять записи, есть ограничение UNIQUE/PK, объём данных средний                                      | Автоматическое обновление, нет дубликатов по ключу                            | Требует ограничений; медленнее на больших объёмах; нужна дедупликация перед загрузкой             |
| **DELETE + INSERT**    | Удалить старые версии по ключу → вставить все новые данные          | Большие витрины, данные нужно обновлять, нет ограничений UNIQUE/PK, универсальный подход                     | Работает без ограничений; быстро; нет дубликатов; сохраняет историю изменений | Сложная реализация; требует хранения метки времени последней загрузки; несколько транзакций       |
